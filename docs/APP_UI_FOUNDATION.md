# 薰风 B2B APP UI 基础规范

## 1. 视觉基线

整体采用克制的灰白商务界面：浅灰页面承载白色卡片，品牌红只用于主操作、选中态、重要数字和少量品牌识别。参考界面的分组卡片、线性图标、充足留白和清晰文字层级可以借鉴，但不引入其底部五栏、社区、积分、娱乐化插画和消费端运营结构。

基础目标：

- 手机紧凑清晰，单手操作区触控尺寸不小于 44px。
- iPad 不按比例放大字体、圆角和控件，而是增加页面边距、限制阅读宽度并重排为双栏。
- 页面不自行创造新红色、新灰色、近似圆角或随意字号。
- 普通卡片不使用明显阴影，以页面底色、白色表面和细分割线建立层级。

## 2. 核心颜色

| 语义 | Token | 色值 | 用途 |
|---|---|---:|---|
| 品牌主色 | `--primary-color` | `#D7192D` | 主按钮、选中态、品牌要数据 |
| 品牌按下 | `--primary-dark` | `#B91224` | 主按钮按下态 |
| 页面背景 | `--surface-page` | `#F4F5F8` | 页面底色 |
| 卡片表面 | `--surface-card` | `#FFFFFF` | 卡片、列表、弹窗 |
| 次级表面 | `--surface-subtle` | `#FCFCFD` | 轻提示、按下态、数据分区 |
| 主文字 | `--text-primary` | `#1B1C20` | 标题、正文、金额 |
| 次文字 | `--text-secondary` | `#62666F` | 描述、标签 |
| 弱文字 | `--text-tertiary` | `#969AA3` | 时间、占位、尾部值 |
| 分割线 | `--divider-color` | `#ECEEF2` | 列表分隔、卡片边界 |

状态色只使用 `success / warning / danger / info` 四组语义 Token，不直接复用 Element UI 的默认颜色。

## 3. 字体层级

字体和行高使用稳定 px，禁止用 rpx 在 iPad 等比放大。

| 层级 | 字号 | 字重 | 场景 |
|---|---:|---:|---|
| Display | 28px | 700 | 核心金额、首页关键数字 |
| H1 | 24px | 700 | 页面大标题、结果页标题 |
| H2 | 20px | 600 | 区域标题、金额 |
| H3 | 18px | 600 | 卡片标题、商品名称 |
| Body L | 16px | 400/500 | 列表主标签、重要正文 |
| Body M | 14px | 400 | 普通正文、按钮 |
| Caption | 12px | 400 | 时间、辅助说明、状态标签 |
| Micro | 11px | 500 | 角标，仅在空间受限时使用 |

金额使用制表数字 `font-variant-numeric: tabular-nums`，英文变长时允许截断或换行，不通过缩小字号解决。

## 4. 尺寸与间距

- 页面左右边距：手机 16px；平板 24px。
- Header 内容高度：手机 48px；平板 52px；状态栏高度另计。
- 标准输入框与主按钮：48px。
- 紧凑按钮：40px。
- 分组列表项：手机至少 56px；平板至少 60px。
- 图标：普通功能 22px，导航/重点操作 24px；描边约 1.8–2px。
- 间距使用 4/8/12/16/20/24/32/40px 阶梯。
- 控件圆角 10px，普通卡片 14px，重点卡片/弹窗 18px，标签 6px。

## 5. 手机与 iPad

| 可用宽度 | 模式 | 布局规则 |
|---:|---|---|
| `< 600px` | Compact | 单列、16px 页面边距、底部主操作全宽 |
| `600–839px` | Medium | 24px 页面边距、内容最大 720px，可使用两列卡片 |
| `≥ 840px` | Expanded | 内容最大 1120px，账户/摘要在左、业务列表在右，复杂业务使用主从或双栏 |

断点以当前窗口宽度为准，必须响应旋转和 iPad Split View，不能依据设备名称判断。

## 6. 基础组件职责

- `AppPageShell`：页面高度、Header/内容/底部操作区和安全区。
- `AppHeader`：状态栏、返回、标题、右侧动作和沉浸页明暗模式。
- `AppContent`：滚动区、页面边距和最大内容宽度。
- `AppCard`：统一白色表面、边界、圆角和内边距。
- `AppListGroup`：设置/中心类页面的分组卡片。
- `AppListItem`：统一图标、主标签、描述、尾部值、箭头和危险态。
- `AppButton`：主、次、文字和危险按钮。
- `StatusTag`：业务状态语义色。
- `QuantityStepper`：商品或 SKU 数量输入的稳定尺寸。
- `FixedActionBar`：购物车、结算、支付等底部操作内容；定位、占位和底部安全区只由 `AppPageShell` 负责，组件自身不得再次 `position: fixed`。

业务页面优先组合基础组件，禁止复制整段卡片、列表项、按钮和安全区 CSS。

## 7. 下一阶段门禁

- 新页面禁止新增未登记的十六进制颜色。
- 新字体尺寸必须来自 Token；特殊营销画面需单独说明。
- 正式业务页面禁止 Emoji 作为图标。
- 页面禁止手算 `100vh - Npx`；使用页面壳的 flex 滚动区。
- Expanded 页面必须明确选择限制阅读宽度、双栏或主从布局，不能把手机页面拉满。
- 提交前至少检查 390×844、768×1024、1024×768 三种视口。

## 8. 图标规范

- 字体源只保存在 `src/static/iconfont/`，由 `src/main.js` 全局加载一次；禁止页面重复引入字体文件。
- 页面和业务组件只能使用 `AppIcon`，传入 `user`、`cart`、`message` 等业务语义名；禁止直接写 `iconfont icon-xxx`、`uni-icons`、内联 SVG 或 Emoji。
- Font-class 的真实类名集中维护在 `src/shared/ui/AppIcon/AppIcon.vue`，升级 Iconfont 项目后只核对这一张映射表。
- 图标使用 `currentColor` 继承文字颜色，标准尺寸为 20/22/24px；页面不得通过单独调整字体粗细制造另一套风格。
- 当前字体包尚缺少精确的“密码锁、隐藏密码、网络断开、物流货车”图标，相关位置暂用安全中心、实心眼睛、警告、车辆图标代替；补齐后保持现有业务语义名不变，只更新映射。

## 9. 第二轮落地范围

- 首页：只保留“商品下单、新闻资讯”两个核心业务入口，不承载商品列表、资讯列表或底部导航。Header 与内容区共享一张连续页面背景，禁止用独立大色块形成断层；手机竖屏使用双卡片纵向布局，768px 以上改为双列。允许使用静态半透明渐变、轻量毛玻璃和阴影建立层级，但禁止持续动画、远程首屏大图和首页接口预取。
- 商品目录：保留手机双列，iPad 竖屏三列、横屏四列；价格、库存和起订量均来自接口适配层。
- 商品详情：手机主图左右铺满并保持正方形，信息卡片统一 12px 分区间距；768px 竖屏限制为 760px 阅读宽度，960px 以上改为左侧主图、右侧采购信息双栏。后台中文介绍在商品参数下方以富文本呈现，其中详情图强制内容区 100% 宽、自适应高度。
- 单规格采购：颜色、尺码、价格、起订量、可购状态均来自 SKU；无库存规格置灰。库存展示遵循保密规则：大于 100 只显示“有货”，小于等于 100 显示实际数量。
- 批量采购：独立页面按颜色分组、尺码纵向排列，支持逐 SKU 填数、一键清空和整行复制；0 表示未选，正数必须满足 SKU 最小起订量且不得超过可用库存。
- 购物车：单规格立即调用 `AddToCart`；批量采购一次调用 `BatchAddToCart`，不得循环请求。购物车内连续改量通过调度器去抖、合并和最终 flush，减少频繁操作造成的接口放大。
- 结算：展示真实已选 SKU，进入确认订单前必须 flush 购物车待同步变更，再调用订单预览与创建接口。

下一轮应继续统一登录/申请表单、消息与新闻列表、订单详情/售后表单，并建立图标资产映射和页面视觉回归截图清单。
